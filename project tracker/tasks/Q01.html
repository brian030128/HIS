Q01

投標資格（Go / No-Go 閘門）

投標當天就要交出四張證明：公司登記、CMMI Level 3、CNS/ISO 27001、BS 10012:2017 或 ISO 27701，另加大陸原產地／陸籍人士禁令的自我聲明。任何一張缺席就不必再談其他任務——這是整個專案樹的根節點，所有 T／H／X／M 任務都以它為前提。

規格原文依據

肆、專案履約能力（投標資格）——投標時須檢附證明文件：

  1. 政府合法登記立案之公司、行號、法人、公會、協會、學會團體等；不受理個人名義。投標時繳交登記或設立證明影本，必要時提供正本查驗。
  2. 通過軟體發展能力評鑑 CMMI Level 3 認證。
  3. 通過資訊安全管理系統 CNS 27001 或 ISO 27001 認證。
  4. 通過 BS 10012:2017「個人資訊管理系統（PIMS）」或 ISO 27701 認證。

摘要「原產地」：允許七大洲；不允許大陸地區標的；聯網／無線通訊組件不得為大陸廠牌或大陸原產（全部地點）。

伍-一-16：禁止使用危害國家資通安全產品；資通訊產品不得使用大陸廠牌，禁止大陸地區廠商及陸籍人士參與。

伍-一-2：更換專案人員應提供資歷供機關審查，經書面同意後始得更換。

我們預期的系統樣貌

這不是技術任務，而是一張決策流程：先確認四張證書「投標當日」全部有效，再確認組成方式（獨資／聯合承攬／分包）是否被招標文件接受，最後盤點人員與供應鏈的原產地。三關全過才進入 M01 的工作計畫書準備。

元件與資料流

  • 證書登錄表：每張證書的發證機構、證書編號、有效期起迄、涵蓋範圍（scope statement）。CMMI 的 appraisal 有 3 年有效期；ISO 27001 每年 surveillance、3 年再認證；BS 10012 亦同。投標日若落在 surveillance 逾期未完成的窗口，證書可能被視為無效。
  • 範圍比對：ISO 27001 證書上的 scope 是否涵蓋「軟體開發與維運服務」；若 scope 只寫「資料中心營運」，審標時可能被質疑。
  • 人員／供應鏈聲明：依伍-一-16 的禁令，需要一份內部盤點——所有擬投入人員（含分包）的國籍、以及 T01 改寫時會引入的第三方套件來源。這份盤點同時餵給 M03 的合規矩陣。
  • 輸出：投標文件附件（證書影本＋正本備查）、原產地切結書、Go/No-Go 決議紀錄。

工作量怎麼估的

約 1 人月：證書蒐集與有效性確認 0.2、向採購組釋疑往返 0.2、人員與供應鏈盤點 0.3、投標文件整理與內部審查 0.3。若任何一張證書需要補做 surveillance 或再認證，時間會由「週」跳到「月」，而且會撞上投標截止日——這是本任務唯一真正的風險。

需要的領域知識與難點

  • 政府採購法的資格審查慣例：規格說「投標時須檢附」，實務上開標當日不合格即為不合格標，沒有補件機會。必須以「投標截止日」而非「今天」檢視有效期。
  • CMMI 版本問題：規格只寫 Level 3，未指明 CMMI v1.3 或 v2.0／v3.0、也未指明 DEV 或 SVC 模型。若我們持有的是 CMMI-SVC 或舊版評鑑，需向採購組確認是否採認。規格未載明，需確認。
  • BS 10012:2017 vs ISO 27701：兩者擇一即可；ISO 27701 必須疊在 ISO 27001 上，若我們只有 27701 而 27001 恰好在換證期，兩張會一起失效。
  • 聯合承攬／分包的證書歸屬：政府採購慣例下，聯合承攬各成員通常須「各自」符合資格，除非招標文件明定「其中一成員符合即可」。分包商的證書一般不算投標廠商資格。規格未載明，需向採購組確認。
  • 原產地禁令的範圍：本案「施作工程：不需要」、無硬體採購，但伍-一-16 的「資通訊產品」在實務上會被延伸到我們交付的軟體所依賴的第三方元件與開發工具。這會限制 T01 的套件選型與 T08 的中台元件（例如某些 MQ／CDC 產品的來源）。

依賴關係

前置任務

  • 無。這是根節點，與 M01 並列為最早啟動的兩件事，但 Q01 邏輯上先於 M01：沒有投標資格就沒有得標、沒有 20 天內的工作計畫書。

依賴本任務的任務

  • 全部任務——M01、M02、M03、M04、T01～T16、H01～H09、X01：Q01 為 No-Go 時全部作廢。
  • M03 直接沿用本任務的人員國籍盤點與第三方元件原產地清單。

硬體／外部設備介接

無。本案「施作工程：不需要」、「搭配新試劑或衛材：無」，投標資格階段不涉及任何設備。唯一與硬體相關的是原產地禁令：若後續 H01～H09 介接的設備由院方另案採購，原產地責任在院方；若我們需自備測試用設備（例如叫號機模擬器、讀卡機），則不得為大陸廠牌。

主要阻礙與風險

  • 證書效期落在投標日之前 — 最致命也最常見。CMMI 評鑑 3 年一輪，若上次評鑑已逾 2.5 年，現在啟動再評鑑也不一定趕得上。
  • 證書 scope 不涵蓋本案服務類型 — 27001 scope 若僅寫「機房營運」，審標委員可質疑；BS 10012 若 scope 未含「受託處理個資」，就醫民眾資料處理的正當性會被挑戰。
  • 聯合承攬釋疑結果不利 — 若各成員須各自具備四證，能組隊的對象大幅縮減。
  • 人員鎖定 — 伍-一-2 讓得標後換人需院方書面同意；投標時列入的關鍵人員（PM、架構師）若在 630 天內離職，是履約風險而非資格風險，但需在投標時就用「角色」而非「姓名」盡量保留彈性。
  • 原產地禁令被擴大解釋到軟體供應鏈 — 一旦成立，需在 T01 開工前建立套件審查程序，否則後期抽換套件的成本極高。

待確認問題

  1. 投標截止日與開標日是哪一天？公告期多長？（規格未載明，需確認）
  2. CMMI Level 3 是否限定 CMMI-DEV？v1.3 的舊評鑑是否採認？是否要求評鑑仍在 CMMI Institute／ISACA 的 PARS 上可查？
  3. 聯合承攬是否被允許？若允許，資格證明是「各成員皆須」還是「合計具備」？
  4. 分包比例上限與分包商是否須報備（伍-一-6 說名單須書面報備，但未說資格要求）？
  5. 「大陸廠牌」是否包含大陸公司持有的開源專案或 NuGet 套件？院方有無白名單／黑名單？
  6. 是否需要押標金？履約保證金比例？保固保證金比例？（影響 M04 罰則計算基礎）
  7. 投標文件是否需附「原產地切結書」與「無陸籍人士參與切結書」的院方制式格式？
  8. ISO 27001 是否接受 2013 版證書，或必須已轉版至 2022 版？（2025 年 10 月後 2013 版證書已全面失效，需確認我們的轉版狀態）
