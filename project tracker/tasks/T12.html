T12

跨院檢查排程查詢與預約（老人醫院 ↔ 成大）

讓老人醫院的醫師開了檢查醫囑後，能直接查成大各檢查科室儀器（CT、MRI、超音波、內視鏡、心導管、核醫……）的排程空檔並替病人預約；反向亦然。老人醫院初期不會有完整的高階影像設備，這個功能會是開院後最高頻的跨院動作。查詢走 T08 中台的「檢查科室儀器排程」副本；預約是寫入，必須以跨院命令進入擁有該儀器的院區「全院排程」／檢查科室系統，由其原生規則（儀器容量、時段長度、顯影劑、禁食、同意書、腎功能）決定。排定後儀器 worklist（經 PACS，H04）與檢查報告系統（#27）都要能對應到跨院病人。

規格原文依據

貳-一-(二)-4：「查詢及預約老人醫院及成大醫院檢查排程。」

貳-一-(二)-7：「……跨院資源共享：掛號資訊、床位資訊、檢查科室儀器排程、開刀房手術排程、檢驗抽血、營養供膳等。」

貳-一-(二)-6：「提供便利的轉檢與代檢流程機制。」（T14，與本任務高度重疊）

貳-一-(三) 須開發之外部介接第 4 項「PACS 系統」；須測試之介接 #27「檢查報告系統」、#19「LIS」。

附錄門診子系統含「全院排程」、「科室作業」；醫療共用含「病患就醫資訊整合」。

規格用「檢查科室儀器排程」一詞，暗示排程單位是儀器（modality）而非科別；但哪些檢查納入（影像？內視鏡？心臟功能？睡眠檢查？）、是否含檢驗抽血（規格另列）、預約是否需先有對方院區醫囑，皆未載明，需在 T07 定案。

我們預期的系統樣貌

檢查排程與手術排程結構相似，但有兩個關鍵差異：（1）檢查通常需要一張醫囑（order）才能排，而醫囑在來源院區開立、執行在目標院區，這正是 T14 轉檢／代檢的核心；（2）排定後必須產生儀器 worklist（DICOM MWL，經 H04 PACS／RIS）讓機台知道要掃誰，而報告要回到來源院區醫師手上（#27）。因此本任務的寫路徑不只是「佔時段」，而是「跨院檢查醫囑＋排程」一組命令。

元件與資料流

  • 讀路徑（T08）：儀器主檔（modality、科室、地點、可做項目）、排程格模板（每台每日時段、每格時長、保留給住院／急診的比例）、已排檢查（跨院視圖去識別化）、停機維護、檢查項目主檔（含準備事項、禁忌、是否需同意書、是否需顯影劑）。成大這些資料在「全院排程」與各「科室作業」子系統，可能不是一張表，需盤點。
  • 寫路徑（跨院檢查預約命令）：ExamBookingCommand{sourceCampus, targetCampus, patientKey, sourceOrderId, examCode, modalityId, slotId, clinicalInfo, contrast, allergy[], eGFR, consentStatus, pregnancy, implants, sedation, idempotencyKey, operator}。目標院區以原生規則排入，並在其 HIS 內建立對應的檢查醫囑／受檢單（否則 RIS/PACS 與報告系統沒有 order 可掛）。狀態：scheduled → checked_in → completed → reported | cancelled | no_show。拒絕碼：時段已佔、儀器停機、禁忌未排除、需先完成 eGFR、需同意書。
  • 病人身分：重用 T09 的跨院病人索引；PACS 內的病人 ID 與 accession number 需能對回來源院區，否則影像與報告會「找不到人」。
  • 報告回流：檢查報告系統（#27）發報告後，來源院區醫師要能在自己 HIS 看到；走 CDC 進中台，或由 #27 直接推送，需與 X01 協調。
  • 院區參數（T02）：檢查項目碼表（兩院是否同一套？含健保代碼與院內碼）、儀器代碼、排程格規則、準備事項文字。

工作量怎麼估的

約 10 人月：全院排程／科室作業資料模型盤點與 CDC 對應 1.5 人月；跨院儀器排程查詢畫面（modality／日期／時段矩陣、去識別化、準備事項）2 人月；預約命令 API 與擁有院區排程服務封裝（含在目標院區建立檢查醫囑、拒絕碼、idempotency、審計）3 人月；與 H04 PACS worklist、#27 報告回流的欄位對齊與測試 1.5 人月；碼表對照參數化、取消／改期、兩院檢查科聯測 2 人月。與 T14 共用命令與病人索引可省 1–2 人月，前提是兩任務同一組人做。

需要的領域知識與難點

  • 儀器容量不是簡單的時段格：CT 依項目（有無顯影劑、部位）時長不同；MRI 依序列組合；超音波依操作者；內視鏡依是否麻醉；核醫依藥物到貨與半衰期。排程格模板每台儀器不同，且技術師會人工調整。
  • 準備事項與禁忌：禁食（含糖尿病用藥調整）、停用 metformin、顯影劑過敏史、eGFR 門檻、懷孕、金屬植入物／心律調節器（MRI）、鎮靜需家屬陪同。跨院預約時病人不在目標院區，準備指示必須隨排程結果回到來源院區並印給病人。
  • 同意書：顯影劑、鎮靜、侵入性檢查需同意書；在哪院簽、電子同意書能否跨院、紙本如何流轉。
  • 醫囑歸屬與健保申報：老人醫院開立、成大執行的檢查，健保申報由誰申報？費用如何拆？這是 T14 轉檢／代檢的核心問題，但本任務的命令欄位設計必須先知道答案（例如需要「代檢」標記與費用歸屬碼）。
  • 住院 vs 門診檢查：住院檢查有優先權與病房運送安排；跨院住院病人（老人醫院住院、到成大做檢查）牽涉救護車／交通與「暫離院」規則。
  • 老人醫院特性：高齡病人 eGFR 常偏低、多重用藥、行動不便、需家屬陪同；跨院檢查的準備事項與交通需特別考慮，訪談時要問是否需「整批跨院檢查日」的排程模式。
  • 影像與報告回流：醫師在老人醫院要看得到成大的影像（H04 PACS 跨院調閱）與報告（#27）；若只排了程、看不到結果，功能只做了一半。

依賴關係

前置任務

  • T08 — 儀器排程、排程格、檢查項目主檔的 CDC 副本是讀路徑唯一來源；報告回流也可能走中台。
  • T02 — 檢查項目碼、儀器代碼、排程格規則、準備事項的院區參數化。
  • T01 — 全院排程、科室作業、門診／住院醫囑系統改寫為 C# 並將排程檢核與醫囑建立移到後端（配合 T04），跨院命令才能在目標院區建立醫囑與排程。
  • T07 — 訪談定義納入哪些檢查、預約是否需先有對方院區醫囑、費用與申報歸屬。
  • T09 — 跨院病人索引／身分比對；部分檢查在成大需先有掛號（醫囑來源），會呼叫掛號命令。
  • H04 — PACS 介接決定排定檢查如何進 worklist、影像如何跨院調閱；跨院 accession number 與病人 ID 對應需與 H04 共同設計（可並行，上線前整合）。

依賴本任務的任務

  • T14 轉檢與代檢 — 代檢流程的排程步驟直接使用本任務的命令；兩任務建議同組人、同一套命令模型。
  • T11 跨院手術排程 — 術前檢查可能觸發跨院檢查預約。
  • T16 老人醫院上線 — 開院後最高頻的跨院動作。
  • X01 — 檢查報告系統 #27、LIS #19 的介接測試需以跨院排定檢查為案例。

硬體／外部設備介接

部分。本任務不直接連接檢查儀器：排程資料在 HIS 與中台之間流動，儀器是透過 PACS／RIS 的 DICOM Modality Worklist（MWL）得知要掃誰，而 PACS 介接屬 H04。判為 partial 的理由：跨院排定的檢查若 worklist 上的病人 ID／accession number 對不回來源院區，影像會變成孤兒、報告回不去，這是本任務要負責的欄位設計，且整合測試必須含 PACS 測試環境與至少一台儀器（或 MWL 模擬器）。

主要阻礙與風險

  • 醫囑歸屬與申報未定 — 跨院檢查誰開單、誰申報、費用怎麼拆，是院方行政與健保問題；沒定案，命令模型無法收斂，且會與 T14 互相等待。
  • 排程真相在技術師手上 — 若成大各科實際以人工調整排程格（加班、插件、依項目改時長），中台的「空檔」與現場不符；需設計科室確認迴圈或接受「暫排」狀態。
  • 病人 ID 與 accession 跨院對應 — PACS 與報告系統以目標院區的 ID 為主，來源院區要能對回；若 T09 病人索引未定，這裡會直接卡住。
  • 準備事項未隨排程回流 — 病人在老人醫院拿不到禁食／停藥指示，到成大被退檢；這是功能失敗的最常見形式。
  • 碼表不一致 — 檢查項目、儀器、準備事項三院各自維護，自動檢核與帶出指示不可能。
  • 與 H04／#27 的整合順序 — PACS 介接落後時只能以 MWL 模擬器驗證，上線風險移到 T16。
  • 與 T14 邊界模糊 — 「預約檢查排程」與「轉檢／代檢」在規格是兩條，實務是一條流程；若分兩組人做會出現兩套命令模型。

待確認問題

  1. 「檢查科室儀器排程」涵蓋哪些 modality／科室？是否含檢驗抽血（規格另列）、心臟功能、睡眠、肺功能等非影像檢查？規格未載明，需確認。
  2. 跨院預約是否需先在目標院區建立醫囑／受檢單？由命令自動建立還是需對方醫師覆核？
  3. 跨院檢查的健保申報與費用歸屬規則？「代檢」與「轉檢」在本任務如何標記？
  4. 準備事項與同意書：在哪院交付病人？電子同意書能否跨院？
  5. 影像（H04）與報告（#27）如何回流來源院區醫師？走中台還是直接推送？

  8. T12 與 T14 的分工：是否同一組人、同一套命令模型？
  9. 斗六分院是否納入？
