H04

PACS 系統介接（開發）

老人醫院的影像檢查醫令要能流到 PACS／RIS，讓 X 光、CT、超音波等儀器從 Modality Worklist 取得病人與檢查資料，影像與報告完成後回到 HIS，醫師在醫囑畫面一鍵開影像。這是放射科作業流程（order → schedule → acquire → report）的整條資料鏈；規格只寫「PACS 系統」，未說老醫 PACS 是獨立一套還是與總院共用、有沒有 RIS、報告走哪個系統。介接本身是軟體對軟體，但 worklist 那一端直接面對儀器，測試需要真的或模擬的 modality。

我們預期的系統樣貌

放射科標準模式（IHE Scheduled Workflow）：HIS 開立檢查醫令並產生檢查單號（accession number），以 HL7 v2 ORM 送給 PACS／RIS 的 HL7 broker；PACS／RIS 據此提供 DICOM Modality Worklist（MWL）給儀器；儀器完成後影像進 PACS，PACS 以 HL7 訊息或狀態回呼通知 HIS「已檢查／影像到達」；放射科醫師在報告系統打報告，以 HL7 ORU 或報告連結回到 HIS。HIS 端另外要負責病人基本資料異動（ADT A08／合併病歷 A40）同步到 PACS，以及從醫囑／病歷畫面帶 accession number 開啟 viewer。若老醫沒有 RIS、PACS 也不做 worklist，HIS 就得自己當 MWL SCP（用 fo-dicom 之類的 .NET 函式庫），這會把難度往上拉一級。

元件與資料流

  • 醫令下送：檢查醫令開立／排程／取消／改期 → ORM^O01（或 OMI／OMG，依原廠）。欄位：病歷號、姓名、性別、生日、檢查項目碼（院內碼 ↔ PACS procedure code 對照）、預約時間、儀器室、開單醫師、accession number。
  • Accession number 規則：三院同一套 HIS 後，檢查單號要全院區唯一且可辨識院區，這是 T02 參數化要處理的規則；若老醫與總院共用 PACS，衝突就是資料災難。
  • 病人資料同步：改名、改生日、合併病歷要推到 PACS，否則影像掛錯人。
  • 狀態回收：已報到、已檢查、影像到達、報告完成（初／確認）。HIS 檢查狀態、住院醫囑執行狀態、跨院檢查排程查詢（T12）都吃這條。
  • 報告與影像檢視：報告內容進 HIS（或只存連結），醫師從醫囑／病歷帶 accession number 開 viewer；viewer 認證方式（token、AD SSO）與 M03 相關。
  • HL7 引擎：MLLP 監聽與發送、ACK 處理、訊息儲存與重送、對照表維護；建議做成通用元件，H04 之外 LIS 等 X01 測試項也可能用到。

工作量怎麼估的

HL7 收發引擎與訊息記錄 1 人月；醫令 ORM 下送與取消／改期、ADT 同步 1 人月；狀態與報告回收、HIS 狀態更新 1 人月；viewer 啟動與 SSO 0.5 人月；檢查項目對照維護 0.5 人月；與 PACS 原廠聯測、模擬儀器測試、上線陪同 1.5 人月；文件 0.5 人月。合計約 6 人月。若 HIS 需自行提供 DICOM MWL SCP（無 RIS 情境），另加 2 人月；若老醫 PACS 與總院共用且只需擴院區碼，可減 1.5 人月。

需要的領域知識與難點

  • 放射科流程與 IHE SWF：order、scheduled procedure step、MPPS、影像到達、報告狀態等概念，以及 accession number／study instance UID 的關係；沒做過 PACS 介接的人容易把「醫令」和「檢查」一對一綁死，實際上一張醫令可能拆成多個檢查、多次補照。
  • HL7 v2 實務：各家 PACS 的 Z-segment、欄位對應和 ACK 行為都不同，conformance statement 是必需品。
  • DICOM 基礎：至少要能讀懂 MWL 的 query keys 與儀器端會用哪些欄位，才能在聯測時判斷是我們的資料錯還是儀器設定錯。
  • 院內檢查項目主檔：院內檢查碼與 PACS procedure code、儀器室、健保醫令碼的多對多對照，老醫是否沿用總院主檔要在 T07 確認。
  • 跨院影像：轉檢與代檢（T14）會有「在老醫開單、在總院照」的情境，影像與報告要回得到老醫，涉及兩院 PACS 是否互通與病歷號對應。

依賴關係

前置任務

  • T01 — 門診／住院醫囑、全院排程改寫成 C# 後才有醫令事件可掛 HL7 發送；HL7 引擎應依 T01 的後端架構設計。
  • T02 — PACS 端點、院區碼、accession 規則、檢查項目對照皆為院區參數。
  • T07 — 老醫影像檢查範圍（有哪些儀器、是否有放射科醫師駐診、報告由誰打）在訪談確認。

依賴本任務的任務

  • T12 — 跨院檢查排程查詢與預約需要老醫檢查狀態與儀器排程回饋。
  • T14 — 轉檢／代檢流程需要影像與報告跨院回傳。
  • X01 — #27 檢查報告系統的介接測試與本任務的報告回收共用同一條路，需一起排測試。
  • T15、T16 — 老醫上線環境需部署 HL7 服務、開通與 PACS 的連線；開院即需影像檢查。

主要阻礙與風險

  • PACS 架構未定 — 獨立或共用、有無 RIS，直接決定介接範圍與是否要自建 DICOM worklist；這是本任務最大的不確定性，必須在工作計畫書階段逼出答案。
  • 原廠配合度 — PACS 原廠常視 HL7 介接調整為另案收費項目；規格只說院方「會請廠商提供介接說明」，沒說原廠要陪測。要請院方把聯測義務放進 PACS 採購合約。
  • Accession／病歷號跨院衝突 — 若老醫與總院共用 PACS 而病歷號體系不同，影像歸戶錯誤是病安事件；需與 T02、T09 的病人主檔規劃一起處理。
  • 狀態回收不完整 — 很多 PACS 只回「影像到達」不回 MPPS，HIS 端的檢查狀態機要能容忍缺步驟。
  • 測試環境 — 沒有 PACS 測試分區與模擬儀器就無法做迴歸測試；與 T15「上線前另建一組對應環境」需一併規劃。

待確認問題

  1. 老醫 PACS 是獨立系統還是總院 PACS 的延伸？影像伺服器放老醫還是總院 DC？（規格未載明，需確認）
  2. 老醫有無 RIS？若無，worklist 由 PACS 提供還是要 HIS 提供？
  3. #27「檢查報告系統」是否就是放射科報告系統，還是涵蓋內視鏡、超音波、心電圖等其他檢查？報告以內容還是連結回 HIS？
  4. HL7 版本與訊息型別（ORM 或 OMG／OMI）、字元編碼（Big5／UTF-8）、是否有 Z-segment？
  5. 病人資料異動（改名、合併病歷）目前如何同步到 PACS？是否已有機制可沿用？
  6. 轉檢／代檢（T14）在總院照的影像如何回到老醫 HIS？兩院 PACS 是否互通？
  7. viewer 是否需嵌入 HIS 畫面，還是外開視窗即可？
  8. 驗收標準：HL7 訊息往返通過即可，還是要從開單到儀器 worklist 顯示、影像回傳、報告回到 HIS 全流程真機驗證？
